- **A manual collection sync run that overlapped another run of the same collection could answer 500
  (#1008).** `POST /api/collection-syncs/{slug}/run` did not take any lock, so a run started while
  the sweep, or another caller, was filling the same content type could create the same entry
  stream and fail on its primary key (Postgres 23505 on `mt_streams`). A run now holds a session
  level advisory lock on its tenant and content type. The route answers 409 while another run holds
  it and runs nothing, and the sweep leaves a due sync whose collection is locked for a later tick.
  The 409 replaces a 500 or a second run that fetched the same source again, and a run that does
  not overlap another answers as before, so `ApiContract.Version` does not move.
