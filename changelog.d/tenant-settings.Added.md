- **Tenants can override module settings.** Modules list sections in `IBarakoModule.SettingsSections` (keys, categories, descriptions, secret or host-only flags), and `GET` and `PUT /api/tenant-settings/{section}` read and write one tenant's values in a single tenant settings document. An unknown section is 404 and an unknown key is 400. Secrets are stored encrypted and never returned. A resolver reads the tenant override, then the stored host default, then configuration. SMTP business mail (`SendForTenantAsync`) uses the tenant's `Email.Smtp` From only when its domain is listed for that tenant in the host setting `Modules:Email.Smtp:TenantFromDomains:<tenant-slug>` (exact match, case-insensitive, empty by default), so a tenant cannot send as a domain the host relay does not own, or as a domain the host listed for another tenant. Any other From falls back to the host sender and logs a warning. Account mail always uses the host sender. A setting with a type (`Mailbox` or `Url`) is checked on `PUT`, and a bad value is a 400 naming the key. Two modules cannot declare the same section name, and `email` is reserved. `Files.S3` and `AI` declare sections, with no runtime use of the overrides yet. A new table, `mt_doc_tenant_settings`, comes from `migrations/5.5.0/896-tenant-settings.sql`, which production applies before the upgrade because it runs `CreateOnly`. The module configuration endpoint shows a tenant caller its own override for tenant-scoped keys (#896, #890).
