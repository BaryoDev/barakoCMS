- **A password hash kept the BCrypt work factor it was made with, forever.** Sign-in verified the
  password and never rewrote the hash, so raising the factor would only ever reach passwords set
  afterwards. A successful sign-in now rewrites a hash below `PasswordHashing.WorkFactor` (11, the
  factor every existing hash already has). A failed write is logged and the sign-in still succeeds,
  and an account with no password, such as one created by social sign-in, is never given a hash.
  Every place a password is hashed now uses that one factor. (#639)
