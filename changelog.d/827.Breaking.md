- **A permission condition key holding a dot is now a reference path, checked when the role is
  saved (#827).** `POST /api/roles` and `PUT /api/roles/{id}` accepted any condition key. A key
  holding a dot is now answered 400 unless it is `Reference.Field`: the first name a `reference`
  field of the rule's content type, the second a Public field of the type it points at, with at
  least one of `_eq`, `_ne`, `_in` and `_nin`, on a rule other than Create, for a content type the
  tenant defines. A key with no dot is saved as before. A stored rule whose key holds a dot also
  changes meaning: it used to match a row whose own data held a key spelled exactly that, and now
  it follows the reference or denies. An entry write keeps keys its type does not declare, so the
  old match let whoever wrote a row satisfy the rule. This tightens request validation, so it is
  part of API contract 6 with the other changes in this release. `ApiContract.Version` does not
  move again.
