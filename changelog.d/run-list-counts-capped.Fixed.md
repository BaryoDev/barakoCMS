- **The run list counted every run of the tenant on each read.** `statusCounts` on `GET /api/workflow-runs` grouped the whole run history, so the read got slower as it grew. Each status is counted up to 1000 now. The response adds `statusCountCap` and `statusCountsCapped` (the statuses that have more than the cap, whose count then reads "1000 or more"). Existing fields are unchanged, and no migration is needed.
