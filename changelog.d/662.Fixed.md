- **`db-assert` and `db-patch` did nothing on the published image, and started a second server
  instead.** The 4.0 schema refusal and `docs/upgrading-to-4.0.md` named `dotnet barakoCMS.dll
  db-assert`, but `ghcr.io/baryodev/barako-cms` runs `BarakoCMS.Suite.dll`, which ignored its
  arguments and booted the web app against whatever database it was pointed at. The Suite host now
  dispatches `db-assert`, `db-patch` and `db-apply` the way the core host does, without applying the
  schema or seeding first, and exits non-zero when a command fails. The refusal message and the
  upgrade doc give the command as arguments to the image (`docker compose run --rm --no-deps app
  db-assert`), and `scripts/suite-db-commands-check.sh` runs the commands against a published Suite
  in CI.
