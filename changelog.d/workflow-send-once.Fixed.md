- **A failed email or SMS send, or a taken-over workflow attempt, could send a second message.** A send failure other than `EmailNotSentException`, and any SMS provider failure, is now recorded as `Unknown` and not retried. A takeover of an attempt whose lease ran out counts as an attempt, so an action that keeps stopping its node ends at the limit of five, and UpdateField still applies once because the attempt number it is given does not move. An action that does not pass the idempotency key on, such as Email and SMS, ends as `Unknown` on takeover instead of running again, and so does a lapsed undo. `IWorkflowAction.HonoursIdempotencyKey` (default false) names the actions that pass the key on or derive ids from it, and a receiver that ignores the key or a build provider may still act twice. A failed Halt-policy email now ends `Unknown`, so it no longer starts compensation, which only a `Failed` action does. The API contract version does not move.
