- **One contract number covered every HTTP surface, so an admin-only change would stop a renderer
  that checked it.** The delivery surface (the routes under `/api/public/` and the anonymous tenant
  lookups) now has its own number. Every response carries it on `X-Delivery-Contract-Version`,
  beside `X-Api-Contract-Version`, and a browser may read both cross-origin. `GET /api/meta` adds
  `deliveryContractVersion`. The delivery number starts at 6, the value the single number had when
  the two were split. `X-Api-Contract-Version` and `apiContractVersion` keep their name, type and
  value and now mean the admin surface, so a console needs no change. All additive, so
  `ApiContract.Version` does not move (#902).
- **A module had nowhere to state the version of its own endpoints.** `IBarakoModule` gains
  `HttpContractVersion`, with a default of `0` for unstated, so an existing module compiles and
  behaves as before. `GET /api/meta` adds `moduleContractVersions`, one `{ name, version }` entry
  per enabled module, for a caller who holds `view_modules`. Any other signed-in caller gets no
  such field, and a module the enabled list left off is not listed. The member ships in
  `BarakoCMS.Abstractions` 4.6.0 and does not move `ModuleContract.Version`. `BarakoCMS.Pages`
  4.2.2 declares the number its bodies already carry as `contract` (#902).
