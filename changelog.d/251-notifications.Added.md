- **A Notifications module.** `BarakoCMS.Notifications` lets any module tell a user something happened: resolve `INotificationService` and call `RaiseAsync`. The notification lands in that user's inbox (`GET /api/notifications`, `GET /api/notifications/unread-count`, `POST /api/notifications/{id}/read`, `POST /api/notifications/read-all`) and is handed to every registered `INotificationSink`. A user sees and marks read only their own, per tenant. Email delivery through the host's `IEmailService` is a built-in sink, off until `Modules:Notifications:EmailDelivery:Enabled` is true. `POST /api/notifications` and `GET /api/notifications/admin` need the new `manage_notifications` capability, granted to Admin. The table is created by `migrations/5.2.0/notifications.sql`.
