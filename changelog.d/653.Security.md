- **An API key scoped `content:write` could erase content irrecoverably.** `ApiKeyScopeProcessor`
  told read from write by HTTP method alone, so `DELETE /api/contents/{id}/erase` and
  `POST /api/contents/{id}/rollback/{versionId}` counted as ordinary writes. The key was still bounded
  by its owner's capabilities, so this was never an escalation past the owner. Both routes now need
  the new `content:destructive` scope, and a key without it gets 403. An existing `content:write`
  key loses erase and rollback and keeps everything else; a `*` key is unchanged. Scope names are
  listed in `docs/access-control.md`. The console signs in with a user token rather than a key, so
  the contract version does not move. (#653)
