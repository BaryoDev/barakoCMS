- **Workflows never ran with `Tenancy:DatabaseEnforcement` on.** The workflow runner and the run
  and webhook delivery retention sweeps found their tenants with a `select distinct tenant_id` on a
  bare connection. Row level security filters that query on `app.tenant_id`, which a bare
  connection does not set, so it failed or saw one tenant, and queued runs were never picked up.
  The job queue worker had the same gap through `AnyTenant()` on a default session, which the
  policy holds to the default partition, so jobs queued in any other tenant were never claimed,
  cancelled or purged. With enforcement on these now list tenants from the registry (active and
  inactive, plus the default partition) and query each one inside its own tenant session. With
  enforcement off nothing changes.
