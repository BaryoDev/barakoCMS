- **With `Tenancy:DatabaseEnforcement` on, the startup pass that encrypts stored workflow credentials did nothing.**
  It listed tenants with a query the row level security policy refuses, logged the error and
  stopped, so credentials saved before 4.2 stayed as they were. It now lists tenants the way the
  workflow runner and the retention sweeps do: every registered tenant, active or not, plus the
  default partition. Restart the API once after upgrading and it encrypts them. A workflow in a
  partition with no `Tenant` document is not reached, so register that tenant first. With
  enforcement off nothing changes.
