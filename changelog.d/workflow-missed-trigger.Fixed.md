- **A workflow run could be lost for good when the database failed while it was being queued.** The failure was logged and the event was never tried again. It is now kept as a missed trigger, committed with the projection's own batch, and replayed by the scheduled sweep, once per event. A run queued for an event is now inserted under an id taken from the workflow, the entry and the event, so two writers cannot queue it twice. A trigger that fails ten replays is logged as stopped and left alone. To retry it, run `UPDATE public.mt_doc_workflow_missed_triggers SET data = jsonb_set(data, '{Attempts}', '0') WHERE (data ->> 'Attempts')::int >= 10;` as the role that owns the tenant. Run `migrations/5.5.0/workflow-missed-triggers.sql` before deploying, or let `CreateOnly` create the table on first boot.
