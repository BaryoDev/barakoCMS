- **Production refuses to start with open host filtering or a weak first admin password, and sends stricter response headers.** Set these before you upgrade. `AllowedHosts` (environment variable `AllowedHosts`) must list the host names the API answers to, for example `api.example.com`, separated by `;`. A value of `*` or an empty one stops startup outside Development, and the error names the setting. To accept any host on purpose, set `Security:AllowAnyHost` to `true` (`Security__AllowAnyHost`), which logs one warning. A Kubernetes `httpGet` probe sends the pod address as `Host`, so add a `Host` header to the probe when you list real hosts. `InitialAdmin:Password`, when set, must be at least 12 characters, must not equal the user name or its email, and must not be an example value from the docs or compose files (`changeme-in-production`, `change-me-to-a-strong-password`, `local-only-password`, anything starting `REPLACE_THIS`, and similar). Left unset, the first boot still generates one. Development is unchanged. The shipped compose files and Kubernetes manifests set `AllowedHosts` already: `docker-compose.prod.yml` uses `ALLOWED_HOSTS`, else `DOMAIN_API`; `docker-compose.hub.yml` and `quickstart/docker-compose.yml` use `ALLOWED_HOSTS`, else `localhost;127.0.0.1`; `k8s/01-configmap.yaml` sets it to the Ingress host and the probes in `k8s/05-deployment.yaml` send it as `Host`. Outside Development the Content-Security-Policy now adds `frame-ancestors 'none'`, `base-uri 'self'`, `form-action 'self'` and `object-src 'none'`. Every response adds `Permissions-Policy` (camera, microphone, geolocation, accelerometer, gyroscope, magnetometer, payment and usb off), `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Resource-Policy: same-origin`. File downloads (`/api/files/{id}` and `/api/public/files/{id}`) send `Cross-Origin-Resource-Policy: cross-origin`, so a front end on another origin still loads stored images and media. `AllowedHosts` entries `0.0.0.0` and `[::]` count as open, like `*`. `BarakoTestHost` defaults `AllowedHosts` to `localhost;127.0.0.1`, so a test host run as Production starts; override it with `Settings["AllowedHosts"]`. `docker-compose.prod.yml` also lists the service name `app` in its default, for callers inside the compose network.
