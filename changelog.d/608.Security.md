- **The workflow execution log stored exception messages and unredacted parameter values, and
  `GET /api/workflows/{id}/debug` served them.** A failed action recorded `ex.Message`, which can
  carry a recipient or a provider's error body, and every parameter except credential-named ones,
  so an email `To` or a webhook `Url` reached anyone who can read workflow runs. The log now records
  the exception type only, and keeps a parameter's value only when its name is on a short allowlist
  of structural names (`ContentType`, `Status`, `Field`, `TargetId`, `Request`, `TriggerEvent`,
  `RunId`, `WorkflowId`, `Attempt`); other values read `[redacted]`. Logs stored before this are
  redacted when served: their parameter values get the same allowlist and their error messages are
  withheld. The dry-run response still shows the resolved parameters to the author who sent them.
  Logs gain a `redacted` field. (#608)
