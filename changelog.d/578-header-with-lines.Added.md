- **A content type can take lines, and a header is read with them.** `PUT /api/content-types/{name}/lines` declares a child type and the single reference field on it that points back at the header (`null` clears it), and optionally `totalField` and `lineAmountField`, which hold the header's number field equal to the sum of the lines' number field. `POST /api/contents` on a type that declares lines accepts `lines`, up to 200 entries of the child type, and writes the header and every line in one transaction: a refused line (reported as `Line N: ...`) or a total that does not match stores nothing, and `dryRun` stores nothing. Each line takes the header's status and sensitivity, and the server sets its parent field. The response carries `lineIds`. `GET /api/contents/{id}/lines` returns the header and the lines the caller may read in one query, scoped to the caller's tenant. `contentTypes` responses carry `lines`. A type that declares none is created exactly as before. Cascade on delete is not part of this yet.
