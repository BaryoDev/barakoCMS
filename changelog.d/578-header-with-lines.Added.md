- **A content type can take lines, and a header is read with them.** `PUT /api/content-types/{name}/lines` declares a child type and the single reference field on it that points back at the header (`null` clears it), and optionally `totalField` and `lineAmountField`, which hold the header's number field equal to the sum of the lines' number field. `POST /api/contents` on a type that declares lines accepts `lines`, up to 200 entries of the child type, and writes the header and every line in one transaction: a refused line (reported as `Line N: ...`) or a total that does not match stores nothing (a line amount that is missing or not a number is refused by name, and a header with a total and no lines must total 0), and `dryRun` stores nothing. Each line takes the header's status and sensitivity, and the server sets its parent field. The response carries `lineIds`. The total is checked after the hooks and numbering have run, on the values that will be stored, and again on `PUT /api/contents/{id}` for the header and for any line of it, and on `POST /api/contents` of a single line that points at an existing header (a line write that breaks its header's total is refused, naming the header). Only a parent reference in the canonical lowercase or uppercase `D` form (with hyphens, no braces) counts as pointing at a header. It is checked on create and update only, not on rollback, bulk import or workflow actions. The total field and the line type's parent and amount fields cannot be renamed or removed while the lines name them. `GET /api/contents/{id}/lines` returns the header and the lines the caller may read in one query, scoped to the caller's tenant, (the list stops at 200 and `truncated` says so). `contentTypes` responses carry `lines`. A type that declares none is created exactly as before. Erasing a line (`DELETE /api/contents/{id}/erase`) is not checked against its header's total, because an erasure request must not be blocked by it, and erasing a header does not erase its lines. Cascade on delete is not part of this yet. The total is enforced only by the content endpoints named here, so a write that does not go through them (a module storing documents directly, for one) is not held to it.
