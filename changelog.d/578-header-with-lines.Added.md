- **A content type can take lines.** `PUT /api/content-types/{name}/lines` declares a child type and the single reference field on it that points back at the header (`null` clears it). `POST /api/contents` on a type that declares lines accepts `lines`, up to 200 entries of the child type, and writes the header and every line in one transaction: a refused line (reported as `Line N: ...`) stores nothing, and `dryRun` stores nothing. Each line takes the header's status and sensitivity, and the server sets its parent field. The response carries `lineIds`. `contentTypes` responses carry `lines`. A type that declares none is created exactly as before. Reading a header with its lines in one query, cross-set invariants and cascade on delete are not part of this yet.
