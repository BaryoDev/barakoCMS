- **One content-type create could inflate every later content-types list for good.** Nothing capped
  how many fields a type holds, so a single `POST /api/content-types` with 50,000 fields was
  accepted and `GET /api/content-types` returned about 10MB on every call after it. Pagination does
  not help when one item is unbounded, and no endpoint deletes a type. A type may now hold at most
  200 fields, set by `ContentTypes:MaxFields`. Create, `POST /api/content-types/{name}/fields`, the
  SEO fields endpoint, blueprint apply and `POST /api/portability/import` refuse to go past it with 400. A type already stored with
  more keeps working: it is read, delivered and written to as before, and only adding a field to it
  is refused. See the Breaking entry for the contract version. (#650)
