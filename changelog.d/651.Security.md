- **Any container on the production stack's Docker network could set the client IP.**
  `docker-compose.prod.yml` trusted `X-Forwarded-For` from all of `172.16.0.0/12`, the whole Docker
  bridge range, so a container that could reach `app:8080` directly was able to write the IP that
  the audit log records and the per-IP rate limiter keys on. Caddy now sits on its own `proxy`
  network with a fixed subnet (`PROXY_SUBNET`, default `10.87.51.0/28`) and a fixed address
  (`PROXY_ADDRESS`, default `10.87.51.2`), and the app trusts only that address.
  `TRUSTED_PROXY_NETWORK` is still read and now defaults to empty, so a deployment that set it
  explicitly trusts what it did before, plus Caddy. A deployment that relied on the default keeps
  real client IPs. If the default subnet overlaps a network already on the host, `up` fails and
  `PROXY_SUBNET` and `PROXY_ADDRESS` need setting; see the upgrade note in
  `docs/deploy-in-production.md`. The quickstart compose gains `TRUSTED_PROXY_ADDRESS` for naming a
  single proxy. (#651)
