- **A content type name is matched ignoring case.** Config apply and `POST /api/content-types` store the name lowercase while a module keeps the case it seeds, so `triggerContentTypes: ["Order"]`, `schedule.contentType`, workflow triggers, transitions, listing and the other definition lookups failed on a case difference. Permission lookups prefer the exact spelling and never match a different name. A name matching two stored types that differ only by case, with none exact, is refused (400 on create and list, no grant in permissions).
