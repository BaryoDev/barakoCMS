- **This is a breaking change shipped in a minor release: 5.5.0 removes the business modules and the stock reservation primitive.** Eighteen packages leave the repository and get no 5.5 build: BarakoCMS.Payments, BarakoCMS.Booking, BarakoCMS.Scheduling, BarakoCMS.Services, BarakoCMS.Contacts, BarakoCMS.Comments, BarakoCMS.Tagging, BarakoCMS.Documents, BarakoCMS.Forms, BarakoCMS.Reports, BarakoCMS.Notifications, BarakoCMS.Qr, BarakoCMS.Pwa, BarakoCMS.Analytics.Umami, BarakoCMS.CdnPurge, BarakoCMS.Secrets.Aws, BarakoCMS.Secrets.Gcp and BarakoCMS.DeviceTrust. Their 5.4 versions stay on nuget.org, but they must not be used with core 5.5: BarakoCMS.Tagging used core internals, and none of them is built or tested against 5.5. Remove each package reference before you upgrade core, and remove each removed module name from `BarakoCMS:Modules:Enabled` too, because the host refuses to start on a name it does not know.
  - **Your data is not touched.** A database that ran these modules starts on 5.5.0 without errors and keeps every table. The migration runner lists their old ledger rows as `not-loaded` and carries on. Nothing is dropped for you.
  - **Dropping the tables is up to you.** Each module's drop script is in `migrations/removed/drop/` (`payments.sql`, `booking.sql`, `scheduling.sql`, `services.sql`, `contacts.sql`, `comments.sql`, `tagging.sql`, `documents.sql`, `forms.sql`, `reports.sql`, `notifications.sql`, `pwa.sql`, `devicetrust.sql`). Qr, Analytics.Umami, CdnPurge, Secrets.Aws and Secrets.Gcp made no tables. Each script is safe to run twice and, for a module that recorded ledger rows, deletes them from `public.barako_migrations`. Take a backup first. If you replace a removed module with another package that keeps using its tables, do not run that module's drop script. It deletes the data the replacement reads. The original forward and rollback files moved to `migrations/removed/<version>/`, and `migrations/removed/README.md` says what is in there.
  - **Secrets.Aws and Secrets.Gcp.** Point the host at your cloud vendor's own configuration provider for AWS Secrets Manager or Google Secret Manager instead. The `JWT:Key`, `Secrets:Key`, `Connectors:Key` and `Mfa:Key` settings are read the same way as any other configuration key.
  - **Stock reservations are removed.** `IStockReservations`, `StockHold`, their table setup (`barako_stock_counters`, `barako_stock_holds`, `barako_stock_movements`) and the hold sweeper are gone from core. The drop script is `migrations/removed/drop/stock-reservations.sql`. It also deletes the core ledger row. `INumberAllocator` stays public.
  - **Device checks.** `IDeviceGate` and its no-op default stay in core. With BarakoCMS.DeviceTrust gone, no device is ever refused.
  - **Accounting is deprecated.** BarakoCMS.Accounting is marked `[Obsolete]` and is removed in 6.0 (#1285). It keeps working in 5.5.
