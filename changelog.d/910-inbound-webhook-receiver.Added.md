- **Core has one inbound webhook receiver primitive.** `IInboundWebhookVerifier` checks a provider signature (`Hmac` or `Svix`), refuses a timestamp more than five minutes from now, and runs the handler once per provider event id. A replay answers 200 and is not processed again; the handled ids are `InboundWebhookEvent` documents in the new `inbound_webhook_events` table (`migrations/5.2.0/910-inbound-webhook-events.sql`). `POST /api/webhooks/resend` now uses it, with the same route and the same 401 and 200 answers, so a replayed bounce no longer writes a second `EmailEvent`. Connector inbound config and payments adopting it are still open on #910.
