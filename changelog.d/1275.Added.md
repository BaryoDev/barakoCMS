- **The activity feed's event read had no index to use.** `mt_events` was indexed on the sequence and the stream only, so reading content events by time scanned every event of the tenant. `migrations/5.6.0/event-tenant-timestamp-index.sql` adds `mt_events_idx_tenant_timestamp` on the tenant, timestamp and sequence, built `CONCURRENTLY`, and the feed's cursor read now states a plain lower bound on the timestamp so Postgres can walk the index. The 7 day lookback stays. Marten cannot declare an index on `mt_events`, so a new database needs `db-migrate` to get it too.
