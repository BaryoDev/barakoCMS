- **`db-migrate` creates the tables a release adds, so `db-assert` passes before the API starts.** A release that added a document type (for example the API key pairing tables, or a module's error log) made `db-assert` exit 1 listing only tables that did not exist yet, and the upgrade notes say not to start the API after that. After the ledger run, `db-migrate` now creates the tables, functions and indexes the loaded modules declare that are missing entirely, the way a `CreateOnly` start does. A table that exists is never altered, so drift on one (an extra or missing index, a changed column) still fails `db-assert`. `db-migrate --status` lists each missing table as `pending    create <name>` and writes nothing.
