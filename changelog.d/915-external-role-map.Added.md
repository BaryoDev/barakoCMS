- **A tenant can map an identity provider claim to roles.** `PUT /api/tenants/external-role-map` takes a claim name (for example `groups`) and rules from a claim value, read from one configured OpenID Connect provider, to a role in that tenant, with `GET` and `DELETE` beside it, and each change is audited. When someone signs in through that provider for that tenant, each rule their token matches adds its role to their membership, creating the membership if they have none, in the same commit as the sign-in. A person with a second factor enrolled is given the mapped roles when `/api/auth/mfa/verify` passes, from a grant carried in the signed MFA challenge and checked again there. It only adds, never touches a removed or suspended member, and refuses SuperAdmin, platform roles, other tenants' roles and rules on profile claims a person can edit (name, email, phone_number, address and the like). A rule takes an optional `issuer`, matched exactly against the token's issuer, and it is required for a provider whose issuer is a template (Entra common or organizations), since the provider name alone matches every directory. A map can create a membership in a tenant whose sign-up is Closed, for someone who already has an account. Sign-in already finds a returning person by issuer and subject, so a changed email keeps the same account. `GET /api/users/{userId}/external-identities` and `DELETE /api/users/{userId}/external-identities/{id}` list and remove a user's provider links, for a platform administrator (`manage_users`) only, a removal is audited, and a holder of `manage_users` who is not a SuperAdmin cannot reach a SuperAdmin's links. `BarakoCMS.ExternalAuth` is 4.7.0 and adds the `external_role_maps` table (`migrations/5.1.0/915-external-auth-role-maps.sql`). Per-tenant provider configuration is still open on #915.
