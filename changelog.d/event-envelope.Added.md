- **Content events carry a branch, a node and an origin sequence.** Every content event is stamped with `branch-id` (the request's `X-Branch-Id`), and, when `Barako:NodeId` is set, `origin-node-id` and a gapless `origin-sequence` per node. A content type with `BranchScoped: true` refuses a create without a branch, and `Content.BranchId` keeps the branch the entry was written in, rebuilt from the headers. `X-Branch-Id` must be one of the ids in the member's `branches` profile attribute, else 403. Access rules read the row's branch as `$branch` and the request's as `$CURRENT_BRANCH`. `ContentTypeDefinition` gains `MergeClass` and `BranchScoped`. Apply `migrations/5.1.0/event-headers.sql` before deploying (`rollback-event-headers.sql` undoes it). The profile attribute name `branch` is now reserved for the request's branch: a member write refuses it, and a stored one is ignored, so `$CURRENT_USER.branch` now reads the request's branch. Rename a stored `branch` attribute before upgrading. `BarakoCMS.Abstractions` is 5.1.0.
