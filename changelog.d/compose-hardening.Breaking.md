- **The shipped compose files run read-only and non-root, and start refuses example secrets outside Development.** Set these before you upgrade. `BARAKO_TAG` is now required in `docker-compose.hub.yml` and `quickstart/docker-compose.yml`: pin a version in `.env` or your shell, for example `BARAKO_TAG=5.9.0`. The API port in `docker-compose.yml` and `quickstart/docker-compose.yml` is published on `127.0.0.1` only (`127.0.0.1:5005:8080`); in the quickstart set `API_BIND=0.0.0.0` to reach it from another machine, and put TLS in front first. Every service in the four compose files now runs with a read-only root file system, all Linux capabilities dropped (Caddy adds `NET_BIND_SERVICE`, Postgres adds `CHOWN`, `DAC_OVERRIDE`, `FOWNER`, `SETGID` and `SETUID`, the backup container adds `SETUID` and `SETGID`), `no-new-privileges`, a memory limit and a process limit. The API container runs as uid 1654 with `/tmp` and `/home/app` as tmpfs mounts, and `k8s/05-deployment.yaml` sets the matching pod and container `securityContext` with `emptyDir` volumes on the same two paths. Postgres, Caddy and the backup container still start as root and carry the label `org.barakocms.hardening.root` with the reason. Limits are variables with defaults: `API_MEM_LIMIT`, `API_PIDS_LIMIT`, `API_TMP_SIZE`, `DB_MEM_LIMIT`, `DB_PIDS_LIMIT`, `EXTENSIONS_MEM_LIMIT`, `EXTENSIONS_PIDS_LIMIT`, `BACKUP_MEM_LIMIT`, `BACKUP_PIDS_LIMIT`, `PROXY_MEM_LIMIT` and `PROXY_PIDS_LIMIT`. A value of `0` or `-1` removes a limit, so run `bash scripts/check-compose-hardening.sh --env-file .env docker-compose.prod.yml` before `docker compose up`; it fails on a missing or non-positive limit. Raise `API_MEM_LIMIT` before a large import. The backup container writes its job file under `/tmp`; the optional off-host S3 copy installs `curl` at start and needs `BACKUP_READ_ONLY=false`. Outside Development the app now refuses to start on an example JWT key from the compose files, the quickstart `.env.example` or the docs (`JWT:Key`), and on an example database password such as `postgres`, `change-me-to-a-strong-password`, `changeme-in-production`, `local-only-password`, `password` or anything starting `REPLACE_THIS` (the password in `ConnectionStrings:DefaultConnection`, `DATABASE_URL` or `PGPASSWORD`). The errors name the setting and never repeat the value. Development is unchanged. The container health check is the binary: `dotnet barakoCMS.dll --health-probe [path]` asks `http://127.0.0.1:<port>` (the port from `ASPNETCORE_URLS`, default 8080), sends the first non-wildcard `AllowedHosts` entry as `Host`, defaults to `/health/live`, exits 0 on a 2xx and 1 otherwise, and runs before the web host is built. `BARAKO_HEALTH_PROBE_TIMEOUT_SECONDS` changes its 3 second timeout.
