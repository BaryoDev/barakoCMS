- **A branch scoped type is now enforced on the content routes, not only on the change feed and realtime.** A caller who holds branch A could read, list, update, move, schedule and batch-write entries stamped branch B unless an admin had written a `$CURRENT_BRANCH` rule. Now `GET /api/contents/{id}`, by-slug, history, rollback, runs, schedule, update, status change, erase and the batch transition answer 404 for an entry of a branch the caller does not hold. The list and counts leave those entries out, and paging and totals follow. One service, `IBranchScopeGuard`, holds the rule for the feed and the routes. Types that are not branch scoped are unchanged. See [event-envelope.md](../docs/event-envelope.md#branch-scoped-types).
