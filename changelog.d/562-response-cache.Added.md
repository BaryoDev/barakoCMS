- **Delivery reads can be kept in memory, so a repeat does not reach Postgres.** Set `Delivery:ResponseCache:Enabled` to `true`. It is off by default, so nothing changes until you ask. An entry is keyed on the tenant, the host, the path, the query, the `X-Tenant` header and `Origin`, and holds only a 200 an anonymous caller was sent. A request with an `Authorization`, cookie, `X-Viewer-Token`, `X-Share-Key` or `preview` token is never served from or stored in it. A commit evicts the cached reads by the same tags `Surrogate-Key` sends (the entry, its type, the sitemap), so a publish or an unpublish shows on the next read from that instance. Bounds: `ExpireSeconds` (60), `SizeLimitMegabytes` (64), `MaxBodyKilobytes` (512), `MaxQueryLength` (512). The store is per instance, so other instances expire an entry on their own after `ExpireSeconds`.
