- **A lifecycle transition could only be made through `PUT /api/contents/{id}/status`.** The rules
  lived in that endpoint, so a webhook, a job or a module that had to move an entry either copied
  them or wrote around them. `BarakoCMS.Abstractions` 4.6.0 adds `IContentTransitioner` in
  `barakoCMS.Core.Interfaces`, with `ContentTransitionActor`, `ContentTransitionOptions`,
  `ContentTransitionResult` and `ContentTransitionOutcome`, and the endpoint now calls it. Its
  routes, JSON and status codes are unchanged, so `ApiContract.Version` does not move. The actor is
  stated: a user id is checked through the permission resolver as a request by that user is, and a
  named system actor holds no permissions and is refused unless the caller sets
  `SkipPermissionChecks`, which is off by default and skips read on the type, the transition
  permission and field sensitivity on the values sent. The lifecycle, required fields, validation
  and the before-save hooks apply either way. A system actor's move is recorded with `Guid.Empty`
  on the events and, on the `content.transitioned` audit row, no user and `actor` set to
  `system:<name>` in the metadata; a move made with the checks skipped carries
  `permissionChecks: skipped` there. The transition log lines now come from the category
  `barakoCMS.Infrastructure.Services.ContentTransitioner` (#907).
