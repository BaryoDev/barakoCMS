- **One script leaves the API a database role without superuser.** `scripts/db-app-role.sql` (copied to `quickstart/scripts/db-app-role.sql`, and included by `migrations/tenancy/001-app-role.sql`, which keeps its old path) creates or repairs a login role with `NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS`, sets its password on every run so rotation is a rerun, installs `pg_stat_statements`, and makes the role owner of schema `public` and of every table, view, materialized view, sequence and function in it, skipping objects an extension owns. Inputs are `DB_APP_USER` (default `barako_app`) and `DB_APP_PASSWORD` from the environment, or `-v app_role` and `-v app_password`, which win. It refuses, before changing anything, a role name outside `^[a-z_][a-z0-9_]{0,62}$`, an empty or example password, the role running the script, and any role that is a superuser or bypasses row level security, so the owner cannot lose superuser through it. Runs take an advisory lock and take turns. Statement logging, the statement printed beside an error and `pg_stat_statements` utility tracking are off while the password is set, so it reaches no log or stats view. The previous hand-run script left an existing role's password alone, had no owner guard, did not skip extension objects and did not handle views. `scripts/check-quickstart-backup-script.sh` now also fails CI when the quickstart copy differs.
