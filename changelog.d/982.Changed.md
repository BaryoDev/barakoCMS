- **A push to a branch with an open pull request runs CI once, not twice.** `ci.yml` triggers on
  both `push` and `pull_request`, so each push ran every job twice on one commit, and a job binding
  a fixed port could fail against its own twin. A `gate` job now skips the rest of the push run
  when the branch has an open, mergeable pull request into master, and runs everything when it
  cannot tell. A branch with no pull request yet still gets its push run. The merge queue's own
  branches no longer start a push run beside the `merge_group` one, and the three jobs required on
  master report under another name on `push`, so only `pull_request` and `merge_group` can satisfy
  a required check.
