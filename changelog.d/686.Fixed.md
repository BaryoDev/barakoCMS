- **A host could still fail to start on `42P07: relation "mt_doc_jobs_idx_queue_id" already exists`.**
  The advisory lock from #682 serialised the explicit schema apply, but the other side of the race
  was in the same host: `UseBarakoCMS` starts the job queue workers before `ApplyMartenSchemaAsync`
  runs, and a worker's first poll made Marten create the jobs table and its indexes lazily, outside
  the lock. The workers now wait for the schema apply to finish, or for the host to start, before
  they read job storage.
