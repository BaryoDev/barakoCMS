- **The collection sync lock and the migration ledger lock now take their session locks through `AdvisoryLease`.** Both keep the key they had, so a node on the old build and one on this build still exclude each other during a rolling deploy. A collection sync run, from the sweep or the run endpoint, stands down when its lock was lost before it starts (the endpoint answers 409), and the sweep checks its own lock before each sync. A migration run checks its lock before each file and stops with a `failed` line when it is gone. The migration lock follows `Leadership:RefuseBehindPooler` (default off), so existing deployments start as before. The wait for a busy collection now polls instead of queuing in Postgres.
