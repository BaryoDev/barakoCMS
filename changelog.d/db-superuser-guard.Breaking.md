- **A Production host needs `Database:AllowSuperuser=true` to connect as a superuser.** The API stops at startup when its database role is a superuser, has `BYPASSRLS` or belongs to a managed Postgres admin role, unless `Database:AllowSuperuser` (`Database__AllowSuperuser`) is `true`. Connect as a role without superuser instead: `scripts/db-app-role.sql` creates one, and the compose files and `k8s/04-role-job.yaml` run it. If you use `BarakoCMS.Testing` (it ships as a package) and run `BarakoTestHost` with `EnvironmentName = "Production"` against a container whose role is a superuser, which the default Testcontainers Postgres is, set `o.Settings["Database:AllowSuperuser"] = "true"` in that test. A Development host is not affected. `docker-compose.hub.yml` requires `DB_APP_PASSWORD`, so add it to your `.env` before `docker compose up`. Every startup guard reads Development from the host's `IHostEnvironment` alone, and a host built without one counts as Production, so a hand-built `ServiceCollection` that calls `AddBarakoCMS` needs an `IHostEnvironment` registered to be Development. A host with only `DOTNET_ENVIRONMENT=Development` is Development for the guards and defaults. An `environment` key in `appsettings.json` or any other configuration source does not make a host Development. The Development comparison is case-insensitive in the demo account seeder and the Meta endpoint too. A host's startup also runs the database role check when it never called `ApplyMartenSchemaAsync`, which the lean-core host in `docs/delivering-a-client-project.md` now calls.
