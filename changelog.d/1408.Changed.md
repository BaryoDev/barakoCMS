- **Tokens are minted and validated with the host's own signing key.** Five endpoints and helpers signed through `JwtBearer.CreateToken`, which reads FastEndpoints' process-wide options, so a second host in one process could sign with the first host's key. They now sign through the new `IJwtMinter` (`JwtMinter`, registered by `AddBarakoCMS`), which reads `JWT:Key` from the host's own configuration, and bearer validation uses that same key. The key is checked by `JwtKeyGuard` where it is used, so a weak key added to configuration after startup wiring is refused on first mint and validation. Signed bytes are unchanged for a valid key. Changed signatures, with no compatibility overloads: the `TokenIssuer(IQuerySession, IConfiguration, ILogger<TokenIssuer>, TenancyOptions)` constructor is replaced by `TokenIssuer(IQuerySession, IConfiguration, ILogger<TokenIssuer>, TenancyOptions, IJwtMinter)` and the three-argument `TokenIssuer(IQuerySession, IConfiguration, ILogger<TokenIssuer>)` constructor is removed, so build it through `AddBarakoCMS` or pass all five; `MfaService` takes an `IJwtMinter` as a new last constructor parameter; `MfaChallengeToken.Create`, `StepUpToken.Create`, `PreviewToken.Create` and `ViewerToken.Create` take an `IJwtMinter` as their first parameter, where code that called `JwtBearer.CreateToken` itself should inject `IJwtMinter` and call `Mint(audience, expiresAt, claims)`.
