- **A blueprint, config document or import with bad lines is now refused, and good lines are now stored.** The checks that `PUT /api/content-types/{name}/lines` runs (the line type exists, one level deep in both directions, a single parent reference, number total and amount fields) now run on every save of a type, on the lines as they will be stored: a document that omits `lines` keeps the stored ones, so dropping the total field or the parent field is refused, and so is a document that gives a stored line type lines of its own. The line type may be named in any spelling the route accepts. Config apply and import used to pass the checks and then drop the lines. They now store them in the spelling the lines route stores, and a later apply or import that carries no `lines` keeps the stored ones. Config export and bundle export already wrote them. Only a fault the save introduces is refused, so a tenant whose stored lines already have one can still apply its own export. `PUT /api/content-types/{name}/lines` now also refuses lines on a type that is already another type's line type.
