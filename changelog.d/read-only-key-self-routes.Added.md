- **A module can open a route to read-only API keys.** `Definition.AllowReadOnlyKeySelf()` lets a `bcms_ro_` key bound to a service principal call a self-service route with any method, and `Definition.AllowReadOnlyKeyRead()` lets a read-only key call a route that is a POST only to carry a body, with its scopes and content type limits applied as for a GET. `User.TryGetOwnerId` gives a self-service endpoint the principal id to filter by. Core marks no route, an unmarked route is refused as before, and `ModuleContract.Version` does not move. A read-only key with `monitor:read` can now read `GET /api/monitoring/health`, which the scope check allowed and the read-only check refused, and a read-only bearer on `GET /health/ready` is ignored like any bearer, where it used to answer 403. Rolling back to an earlier release ignores the markers (see `docs/api-key-service-principals.md`).
