- **A members manager could widen a member's roles by editing their profile.** Setting `branches`, or any attribute a role's rule condition reads (`$CURRENT_USER.<name>`, and `$CURRENT_BRANCH` or `$CURRENT_USER.branch`, which read `branches`), can let a role the member holds allow rights the caller never held. Adding a member, updating one and inviting now refuse with a 403 unless the caller holds the value. `branches` always counts, whether or not a role mentions it. For a role the member keeps, only a value being added or changed is checked (each added branch for `branches`, an identical value for any other attribute, compared exactly with no trimming). For a role the request grants, every attribute it reads in the member's resulting profile is checked, changed or not, so setting a value and then granting the role that reads it is refused. The member's global and group roles count, and an empty role list does not skip the check. A SuperAdmin and the tenant's Admin still pass.
