- **Workflow action `Transition` moves an entry through a named lifecycle transition.** It names the `ContentType` it moves, and a target of another type, or of another branch than the triggering entry, is refused. The move goes through `IContentTransitioner`, so the type's rules, required fields, validation and hooks apply and the audit row records the system actor. It runs as the system, so the transition permission is skipped. An entry already in the transition's end state counts as done. The user who saves the workflow needs the transition right on that type and name.
