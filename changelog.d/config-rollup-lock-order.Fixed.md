- **Two saves whose content types roll up over each other no longer deadlock.** A config apply, a blueprint apply and a rollup field's sensitivity change each held the types they write before they asked for the types their rollups read, so an apply of A over X and an apply of X over A could wait on each other until Postgres aborted one with `40P01`. Each now takes every type lock it needs in one pass, lowest normalized name first: exclusive for the types it writes, shared for the rollup sources outside the set. Nothing changes for a save that has no rollups.
