- **A lost refresh answer can be retried once.** A `used` refresh token presented again no longer revokes every session when it was rotated no more than `Auth:RefreshRetryWindowSeconds` ago (default 30, `0` turns it off, at most 300), its successor was never used, the row has a session id and the `X-Device-Id` matches. The retry revokes the unused successor as `superseded`, issues a new one on the same session and is audited as `auth.token.refresh_retried`. Any other replay revokes every session as before. A value above 300 is clamped and a negative or non-numeric one falls back to 30, each with a warning at start. The refresh row gets a nullable `SuccessorId`, with no schema change.
