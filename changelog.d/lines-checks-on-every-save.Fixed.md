- **A blueprint, config document or import with bad lines is now refused, and good lines are now stored.** The checks that `PUT /api/content-types/{name}/lines` runs (the line type exists, one level deep, a single parent reference, number total and amount fields) now run on every save of a type that declares lines, so a text `totalField` or a missing line type no longer slips through apply. Config apply and import also used to pass the checks and then drop the lines. They now store them in the spelling the lines route stores, and a later apply or import that carries no `lines` keeps the stored ones. Config export and bundle export already wrote them.
