- **Each release attaches a production bundle and its OpenAPI document.** `barako-cms-prod-<version>.tar.gz` holds `docker-compose.prod.yml`, `docker-compose.secrets.yml`, `Caddyfile`, `.env.prod.example` and the two scripts the compose file mounts, with a `SHA256SUMS` file for the archive. The compose file and the example env file inside already name that release in `BARAKO_TAG`. A production deploy now needs Docker and the bundle, not a checkout of the repository, and `docs/deploy-in-production.md` says how to download it, check the sum and start it. `openapi-<version>.json` is the document the Suite host serves at the release commit, with Swagger on only for the release job's own host. The release fails before any image tag moves or package is published when the document is empty, has no paths, or differs from `openapi/baseline.json`, and the `OpenAPI contract` job in CI makes the same comparison on every pull request, so a change that adds an endpoint refreshes the baseline in the same pull request, and after the release is written it reads the bundle, the sum and the document back from it. CI builds the bundle from the pull request, unpacks it in an empty directory outside the checkout and starts `postgres`, `app` and `db-backup` from it (`scripts/prod-bundle-check.sh`). `docs/delivery-api.md` says where an instance serves its own document, why its delivery paths differ per instance, and when to turn Swagger on. The shipped images and the repository's own compose file are unchanged, and `openapi/baseline.json` gains the module console card fields it was missing.
