- **An Email step can attach a file an earlier step of the same run produced.** Set `Attachments` to `{{actions.N.name}}`, where step N is an earlier step that captures an output holding the file id and declares the file in `WorkflowActionResult.ProducedFiles` (at most 20 are kept, and the attempt says when more were declared). The file may be private, because the run made it. Attachments go out in the order written, and a run file named twice is attached once. An id typed into a field or a parameter is still refused unless it is public and the entry names it, and the existing count and size limits apply. The step inside a Conditional does not get step outputs, and saving a workflow warns about a run file reference there. `IFileStore` gains `FindForRunAsync` and `OpenForRunAsync` (default implementations throw `NotSupportedException`, which the email step reports as a permanent failure), `WorkflowContext` gains `ProducedFiles` and `Ordinal`.
