- **Set `DB_APP_PASSWORD` before you upgrade.** `docker-compose.prod.yml` and `quickstart/docker-compose.yml` refuse to start without it, because the API now connects as the app role `DB_APP_USER` (default `barako_app`) instead of the database owner. Pick a random value that differs from `DB_PASSWORD`; the job that starts before the API creates the role and sets that password. With `docker-compose.secrets.yml`, add `secrets/db_app_password` and change `secrets/db_connection_string` to the app role's user and password. A deployment that sets `DATABASE_URL` must point it at the app role too. **On the first 6.0 upgrade, run the role job before any `db-migrate` or `db-assert`:** pull, stop the app, run `docker compose run --rm postgres-extensions` and check it exited 0, then `db-migrate` and `db-assert`, then `up -d`. On a 5.x volume the app role does not exist yet, so those commands cannot sign in, and once it exists they fail as a non-owner until the job has run.
