- **A Conditional workflow action never ran its then branch on a real run.** The runner and the
  engine replaced `{{...}}` in `Condition` before the action evaluated it, and the action only reads
  a value from the entry when the token is still there. So `{{status}} == Published` on a published
  entry ran the else branch, `{{contentType}} != Post` on a `Post` ran the then branch, and a field
  value holding `==` or `!=` made the condition unreadable. `Condition` is now handed to the action
  as written, at the top level and for a Conditional nested in a branch, and it is compared against
  the entry. This changes what stored workflows do: a Conditional whose `==` condition holds starts
  running `ThenActions` where it has always run `ElseActions`, and one whose `!=` condition does not
  hold starts running `ElseActions`. Check any workflow that was built around the old result. The dry
  run and the execution log now show a Conditional's `Condition` as written, not with values filled in.
