- **Marten moves from 9.40.0 to 9.49.0 and JasperFx from 2.75.2 to 2.84.1, with one schema step.**
  The new Marten replaces the body of `mt_quick_append_events`, which in 9.40 could write a stale
  version back onto a stream after an append of zero events and leave every later append to that
  stream failing until the row was repaired by hand (Marten #5539). Production runs
  `AutoCreate.CreateOnly`, so a 4.x database needs `migrations/5.0.0/marten-9-49-quick-append-events.sql`
  before 5.0 starts; `db-migrate` applies it, and it can go in while 4.x still serves. The rollback is
  `migrations/5.0.0/rollback-marten-9-49-quick-append-events.sql`. A module or host compiled against
  Marten or JasperFx types has to rebuild against these versions. Marten no longer replays a
  `40001` serialization failure, and stops retrying a command timeout in its default read policy, so
  code that relied on either retry now sees the error.
