- **Each sign-in is a session with its own id.** The refresh row now holds `SessionId`, `SessionStartedAt`, `Device`, `SignInIp`, `SignInMethod`, `LastSeenAt` and `LastSeenIp`, set at sign-in and carried across rotation. Every access token for the session carries a `sid` claim, including the token a tenant switch mints. `SignInMethod` is `password`, `code`, `link` or `social:<provider>`, with `+mfa` after a second factor. Ending a session stores a revoke key `sid:<id>` that the token check and the realtime hub read in the same query as the `jti` check, and revokes the session's refresh row with reason `session_revoked`. A refresh that loses a race to that answers 401 and revokes no other session. Rotation clears `Device`, `SignInIp` and `LastSeenIp` on the used row, and erasing a user blanks them on every row. A refresh row from before this change gets a session id on its next refresh. There is no schema change and no new index: the rows are JSON documents and are read by `UserId`, which is already indexed. Nothing is exposed over HTTP yet, so the API contract version does not move.
