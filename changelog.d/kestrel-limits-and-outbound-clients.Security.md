- **Kestrel connection and header limits are set on purpose, and every outbound HTTP client is accounted for.** A fresh start sets a 15 second request headers timeout, 32 KB total header size, 100 headers, a 130 second keep-alive timeout, 10000 concurrent connections and 1000 upgraded connections, and keeps the framework's minimum request body data rate. Each is a default in code and `Kestrel:Limits:*` overrides it (see `docs/deploy-in-production.md`). The connection caps are new bounds where the framework had none, so a node that held more than 10000 connections needs `Kestrel:Limits:MaxConcurrentConnections` raised. An architecture test now lists every `AddHttpClient` registration and fails when a new one is neither routed through the outbound address guard nor on a named list with the reason its target is set only by the operator. Today the one client a tenant or admin can aim (`ExternalApi`, used by webhooks, connectors, CDN purge and sign-in providers) was already guarded and stays so; the AI, error forwarding and fixed-provider sign-in clients target operator configuration or constants.
