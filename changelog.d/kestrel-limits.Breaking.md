- **Kestrel starts with tighter limits than ASP.NET Core 10 does.** The request headers timeout is 15 seconds (framework: 30). `MaxConcurrentConnections` is 10000 and `MaxConcurrentUpgradedConnections` is 1000 (framework: unlimited), so a node that held more needs `Kestrel:Limits:MaxConcurrentConnections` or `:MaxConcurrentUpgradedConnections` raised, for example above 1000 realtime WebSocket clients at once. The host now binds `Kestrel:Limits:*` over these values, which the framework does not do by itself, so an existing `Kestrel:Limits` entry starts to apply. `Kestrel:Limits:MaxRequestBodySize` is refused at startup with a message naming `RequestLimits:MaxBodyBytes`, the one body size key. A blank connection cap keeps its default, and a zero or negative cap, request headers timeout or keep-alive timeout is refused at startup with a message naming the key. `RequestLimits:MaxBodyBytes` is read when the options are first used, so a value a test host adds late counts.
