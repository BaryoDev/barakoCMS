- **Accounts sit above tenants.** A `TenantAccount` holds tenants, and every tenant not assigned to one belongs to the implicit default account, so a deployment that creates none behaves as before. A user made a manager of an account (`POST /api/accounts/{slug}/managers`) lists and edits only that account's tenants through `/api/tenants`; `manage_tenants` still reaches all of them. An account carries console branding as data: name, logo URL and colours, set with `PUT /api/accounts/{slug}` and read by the console from `GET /api/accounts/branding`, which falls back to the tenant's `Branding` colours. `Tenant.AccountId` is new (null is the default account) and tenant responses and writes carry an optional `accountId`. First slice of #898. Account members and roles beyond the manager grant, and a console that reads the branding, are not in it.
