- **The Kubernetes Postgres StatefulSet and backup CronJob run hardened, and Postgres reports ready only once it takes TCP connections.** `k8s/03-postgres.yaml` sets a `RuntimeDefault` seccomp profile, a read-only root, no privilege escalation and only the five capabilities the compose file adds (`CHOWN`, `DAC_OVERRIDE`, `FOWNER`, `SETGID`, `SETUID`), with `emptyDir` volumes on `/tmp` and `/var/run/postgresql`. `k8s/07-backup-cronjob.yaml` runs as uid and gid 70 with `fsGroup: 70`, a read-only root and no capabilities. The Postgres readiness probe in Kubernetes and the healthcheck in every compose file now run `pg_isready -h 127.0.0.1`, because the image's first-start server listens on the socket only. CI starts Postgres and one backup on kind (`scripts/check-k8s-start.sh`). `k8s/README.md` lists the hosts to set and a test checks that the Ingress hosts and probe `Host` headers are in `AllowedHosts`.
